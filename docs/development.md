# Разработка и сборка

## Окружение

Используйте Python 3.12 или 3.13. Прямые зависимости закреплены в `requirements.txt`; инструменты проверки — в `requirements-dev.txt`. Node.js 22+ требуется только для стандартного тестового раннера JavaScript, `npm install` не нужен.

```bash
python -m venv .venv
# Активируйте окружение согласно README.
python -m pip install -r requirements-dev.txt
python src/app.py
```

Для отделения тестовых настроек от личных:

```bash
# macOS / Linux
PYNDS_SETTINGS_DIR="$PWD/.local/settings" python src/app.py
```

```powershell
# Windows PowerShell
$env:PYNDS_SETTINGS_DIR = "$PWD/.local/settings"
python src/app.py
```

## Проверки

| Команда | Что проверяет |
| --- | --- |
| `python -m pytest` | Расчёты, неверные входные данные, Excel и Word, настройки |
| `python -m pytest --cov` | То же с отчётом покрытия |
| `node --test tests/calculator.test.cjs` | Общие денежные примеры и ошибки ввода в JavaScript |
| `ruff check src tests scripts` | Ошибки Python и порядок импортов |
| `ruff format --check src tests scripts` | Форматирование |
| `python scripts/check_ui.py` | Демопример, редактирование, ставка, валидация, очистка, ширины 390/900/1440 px |
| `python scripts/check_desktop.py` | Реальное соединение Qt WebEngine и Python, загрузка настроек, итог примера |

Для браузерного сценария сначала выполните `python -m playwright install chromium`. На Linux для CI используется `python -m playwright install --with-deps chromium`. Это отдельный тестовый браузер, который не нужен конечному пользователю.

`python scripts/check_ui.py --screenshots` обновляет реальные снимки в `docs/screenshots/`. Команда не создаёт макеты и не подменяет интерфейс. В CI проверки настольного Python-кода выполняются на Linux, Windows и macOS; браузерная проверка — на Linux. Smoke-проверка Qt доступна отдельной командой, поскольку требует работающей графической подсистемы.

## Windows-сборка

В репозитории есть переносимый шаблон `pysidedeploy.spec` без путей к компьютеру автора. Он предназначен для **сборки на Windows** в активном виртуальном окружении Python 3.12. Эта процедура не означает, что готовый бинарный файл уже протестирован или опубликован.

```powershell
python -m pip install -r requirements.txt
pyside6-deploy -c pysidedeploy.spec --dry-run
pyside6-deploy -c pysidedeploy.spec -f
```

Шаблон использует `standalone`: распространяется вся полученная директория с исполняемым файлом, ресурсами и библиотеками Qt, а не отдельный `.exe`. Точный путь результата сообщает инструмент; файлы сборки находятся в `dist/` и `deployment/`. При первом запуске инструмент может установить Nuitka и запросить компилятор. `pyside6-deploy` может дополнить конфигурацию локальными путями — не коммитьте такие изменения.

Перед распространением на целевой машине проверьте запуск без установленного Python, наличие локального `ui/index.html`, импорт Excel, оба экспорта и сохранение настроек в `%APPDATA%`. Для Qt WebEngine также необходимы вспомогательный процесс и его ресурсы; копирования одного исполняемого файла недостаточно.

Официальные инструкции: [pyside6-deploy](https://doc.qt.io/qtforpython-6/deployment/deployment-pyside6-deploy.html), [развёртывание Qt WebEngine](https://doc.qt.io/qt-6/qtwebengine-deploying.html). Лицензии библиотек и условия распространения сборки проверяются отдельно от MIT-лицензии исходников PyNDS.

## Иконка

`src/ui/icon.svg` — собственный векторный знак проекта. `assets/app.ico` получен из него для Windows. Если меняете знак, установите Pillow и выполните:

```bash
python -m pip install pillow==12.3.0
python scripts/make_icon.py
```

## Частые вопросы

**Не найден PySide6 / openpyxl / docx.** Убедитесь, что установка зависимостей и запуск используют один Python: `python -m pip --version`.

**Qt не запускается в SSH или контейнере.** Для обычной работы нужна графическая сессия. В CI для самой предметной логики окно не требуется. Сообщение об отсутствующем Qt platform plugin указывает на системные графические зависимости; используйте инструкцию Qt для своей ОС.

**В Linux отсутствует `libEGL.so.1`.** На Ubuntu установите системные библиотеки Qt:

```bash
sudo apt-get update
sudo apt-get install -y libegl1 libopengl0 libxcb-cursor0
```

Эти пакеты также устанавливаются в Linux-задании CI. Для интерактивного окна по-прежнему нужна графическая сессия.

**Из формульных ячеек не появились цены.** Откройте книгу в Excel или LibreOffice, пересчитайте и сохраните. `openpyxl` не вычисляет формулы, а читает их сохранённые результаты: [документация openpyxl](https://openpyxl.readthedocs.io/en/stable/tutorial.html#loading-from-a-file).

**После перезапуска таблица пуста.** Сохранение настроек не сохраняет товары. Для следующего сеанса экспортируйте и импортируйте Excel.

**Настройки из старой версии не появились.** Новая версия использует папку пользователя. Если нужны прежние реквизиты, перенесите старый `spec_settings.json` туда или заполните их заново. Не переносите личный файл в репозиторий.
