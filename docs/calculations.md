# Правила расчёта

## Контракт входных данных

`normalize_rows(payload)` принимает объект с `vatRate` и списком `rows`, возвращает ставку `Decimal` и нормализованные строки. Функция не импортирует Qt, не открывает диалоги и не записывает файлы.

| Поле | Значение |
| --- | --- |
| `name` | Непустое наименование |
| `net` / `gross` | Хотя бы одна цена, от 0 до 1 000 000 000 |
| `source` | `net` или `gross`; если обе цены есть и источник не задан, приоритет у `gross` |
| `qty` | Положительное количество до 1 000 000; по умолчанию 1 |
| `unit` | Единица измерения, по умолчанию `шт` |
| `gost` | Произвольный текст стандарта |
| `sum_net` / `sum_gross` | Используются для восстановления цены только при отсутствии обеих цен |
| `vatRate` | Число от 0 до 100; по умолчанию 22, округляется до двух знаков |

Допускаются десятичная точка, запятая и разделительные пробелы. `NaN`, бесконечность, отрицательные цены и нулевое количество отклоняются. Пустые строки пропускаются; имя без цены считается незавершённой строкой и не экспортируется.

## Последовательность

1. Проверить ставку и количество; округлить их до 2 и 3 знаков соответственно.
2. Округлить исходную цену до копеек методом ROUND_HALF_UP.
3. Если источник `gross`, вычислить `net = round(gross / (1 + rate / 100))`.
4. Если источник `net`, вычислить `gross = round(net × (1 + rate / 100))`.
5. Вычислить `vat = gross − net`, чтобы обе цены и НДС сходились до копейки.
6. Рассчитать `sum_net = round(net × qty)` и `sum_gross = round(gross × qty)`.
7. НДС строки равен `sum_gross − sum_net`. Итоги документа — сумма итогов строк.

При редактировании импортированной цены прежние суммы не используются. Если в Excel указаны только сумма и количество, цена восстанавливается делением, после чего применяется тот же порядок округления. Из-за округления восстановленная сумма может отличаться от исходной — это осознанное правило учебной модели.

## Почему НДС считается разностью

Формула включённого НДС — `gross × rate / (100 + rate)`. При вычислениях с точностью до копеек независимое округление всех трёх полей может нарушить равенство `net + vat = gross`. Поэтому сначала округляется вторая цена, затем берётся разность.

Например, `gross = 0,03` при ставке 20% даёт `net = 0,025 → 0,03`, а `vat = 0,00`. Если отдельно округлить аналитический НДС `0,005 → 0,01`, получится лишняя копейка. Этот случай включён в тесты.

Для дробного количества НДС строки не всегда равен округлённому произведению `vat × qty`: приоритет у равенства между итогами без НДС и с НДС. Это выбранная политика расчёта, которую нужно пересмотреть при адаптации под конкретную учётную систему.

## Python и JavaScript

Python считает через `Decimal`, браузер — через `BigInt` в копейках. Для количества используются тысячные доли, для ставки — сотые доли процента. Двоичные дроби JavaScript не участвуют в денежных операциях.

[Общие примеры](../tests/calculation_cases.json) проверяются обеими реализациями: нулевая ставка, бесплатный товар, половина копейки, дробные ставка и количество, приоритет цены. Общая сумма документа ограничена 1 000 000 000 000 рублей: это удерживает экспортируемые денежные значения в пределах 15 значащих цифр Excel с учётом копеек.

## Границы модели

Одна ставка на документ; возвраты, скидки, ставки по строкам и валюта кроме рублей не моделируются. Ставка 0% в этой программе означает арифметический ноль и не кодирует правовое различие между ставкой 0% и освобождением от НДС.
